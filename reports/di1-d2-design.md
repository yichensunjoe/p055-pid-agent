# DI-1-D2 设计方案 + CODE GO 申请

状态：Design Proposal（待 Gate Design 裁定 + CODE GO）。依据：Charter §55D（v1.3.0）、DI-1 定义（`reports/di1-definition.md`，Gate 2026-10-12 APPROVED）、Gate 切片顺序裁定（D2 = Design Proposal + CODE GO Request，不直接实现）。

Owner 指令约束（全程有效）：快捷实用稳定高效、以真正画出用户想要的流程图为目的、不要过度工程化。本设计的一切取舍按此排序：**用户出图成功率与速度 > 架构纯度**。

## 1. 现状关键事实（只读摸查结论，证据见引用）

**两条 NL 前门并存**：

| | 链路 A：plan-v2（生成式） | 链路 B：text-plan（判读式，M7 主线） |
|---|---|---|
| 几何归属 | **模型给坐标**（M7 缺陷登记册 P0 `model_owns_low_level_geometry` 判死刑的模式） | 代码拥有全部几何（`auto_layout_semantic.py` / `m7_layout_materialization.py`） |
| LLM 角色 | 生成整份语义事务 | 只做选择题（选型号/连接对/消歧 tag），置信度 <0.34 跳过不猜 |
| 实测耗时 | 本地 35B 约 4.5 分钟首稿；LongCat 106.8s/48 操作 | 亚秒级判断 + 毫秒级确定性排版落库 |
| 已知失败模式 | 首稿错选设备、漏接系统边界（归因模型指令遵循，未结构性消除） | 「换成」「系统声明」等语法直接 receipt 诚实拒绝；G3/G4/TT-101 等冻结 gap |
| 修改闭环 | replan（≤5 次），与 B 不互通 | text-edit 作用于存储 DiagramSpec，整图原子重画 |

**改图闭环三个硬边界**（全是当前实现事实）：① 刷新页面即断链——`nlSource` 只是 React 内存态，`store.latest_semantic_spec` 无 GET 端点暴露；② 非 NL 来源图纸 422 `semantic_source_unavailable` 拒改；③ 人工碰过像素即漂移拒改（`m7_redraw.py` 逐点比对）。

**F4（交互速度）无基线**：埋点已存在（每次 plan/text-plan 写 `duration_ms`），但无任何延迟汇总报告；散点横跨两个数量级且分属两条链路。

## 2. 核心设计决策（请 Gate 逐项裁定）

### D2-1：NL 前门归一到判读式链路 B

**提案**：DI-1 以链路 B（text-plan / text-edit）为唯一主力 NL 出图路径；链路 A（plan-v2 生成式）在 DI-1 期间**降级为实验路径**——默认入口不再暴露给用户场景评测，代码保留不删（避免大爆炸重写，Charter §30）。

理由：链路 A 的「模型拥有坐标」正是 M7 P0 判死模式，分钟级耗时与首稿错选/漏接属结构性而非参数问题；链路 B 已证明亚秒级判断 + 确定性几何 + 原子落库 + spec 级编辑闭环。Owner 指令下，把资源投进已验证的链路是快捷实用的唯一选择。

**需要 Gate 裁的边界**：链路 A 的「降级」口径（UI 入口文案/默认开关/文档表述）在实现片冻结；不删除任何既有 API（非回归要求）。

### D2-2：修通改图闭环的第一边界（刷新断链）

**提案**：`GET /documents/{id}/nl-source` 只读端点，暴露 `store.latest_semantic_spec` 的存在性、revision 与 specDigest（不含 spec 本体以外的任何新写路径）；前端加载文档时用它恢复「改图」可用态。这是唯一需要新增的表层（read-only）。

边界②（非 NL 来源拒改）与边界③（人工漂移拒改）**本期保持不动**：它们是诚实拒绝而非缺陷，放开需要语义反推能力，属未来切片。

### D2-3：已冻结 gap 清单逐条闭环

M8-Q1/Q2 冻结语料跑出的用户可见 gap：G4 泄放支路不可走线、G3 回流/侧线 selector 词表、TT-101 温度变送器符号缺失、「换成」语法不识别、系统声明子句。每条在 DI-1 场景语料中落一个断言：**已修通**或**仍诚实拒绝**（不允许无声失败）。修复本身按子句语法/符号目录/走线白名单的小切口实现，不做通用语法引擎。

### D2-4：生成时即跑图面质量门禁并写进回执

text-plan 落库后自动跑既有 diagram quality 检查（碰撞/共线/正交性），把分数与 blocker 计数写进响应回执与诊断事件。drawing usability 的人工评价记录因此有一个客观锚点（分数）+ 主观锚点（人工五行记录），usability 不再全靠事后人看。

### D2-5：先测基线再冻 F4

实现片第一步是测量：对冻结场景集按链路 B 实测首稿/改图延迟（median-of-5），形成 `reports/di1-latency-baseline.json`；F4 达标线在该基线上由 Design 复核冻结（例如「首稿 ≤ 基线 p50 的 1.2 倍」量级），不在本提案预设数字。

## 4. 三指标测量口径（F2）

- **semantic correctness**：生成图的工程语义（元件类型/位号/连接/方向）与场景期望逐条比对——确定性断言，机器判。
- **drawing usability**：① 生成回执的图面质量门禁分数 ≥ 冻结线且无 blocker；② 人工评价「是我要的图 / 不是」+ 一句话理由（Owner 或指定工程师，五行记录内）。
- **deterministic replay**：同一场景同一输入跑两次（fresh process），语义结果一致（复用 M5 语义哈希方法论）。

## 6. 风险与负例

| 风险 | 处置 |
|---|---|
| 链路 B 子句语法覆盖不足导致场景失败 | 诚实 receipt 是特性不是 bug；场景断言区分「已修通/仍拒」，绝不把拒识包装成成功 |
| 只读端点暴露语义源被当作写旁路 | 端点 GET-only、零审计写，进 `surface_contract.py` 登记为 read，测试钉死 |
| 基线测量机器噪声 | 与 M13 裁定同一口径：median-of-5、样本全列、不外推、不作 CI ceiling |
| 人工评价主观性 | 评价人/理由/时间如实记录；评价不作为机器门禁，只作 F2 证据 |
